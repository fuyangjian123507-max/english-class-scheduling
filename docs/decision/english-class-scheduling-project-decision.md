# 外教一对一英语课排课平台：项目决策讨论稿

文档状态：讨论稿，尚未形成项目立项、采购或收费决定。
编写日期：2026-09-05。
依据：[架构设计](../architecture/english-class-scheduling-architecture.md)；参考：[典型工作流](../architecture/english-class-scheduling-workflows.md)。

本文用于讨论“是否值得做、做到哪里、需要投入多少、谁来长期负责”。

## 1. 建议先作出的判断

建议以有限预算开展小范围试运行，通过试运行真实使用验证管理时间是否下降、课时记录是否可靠，再决定是否向完整用户群全量开放。

立项的必要条件是：有明确的业务负责人、技术维护人和费用承担方，班长愿意持续维护课表与处理审核，并且参与者接受统一的预约和课时规则。即使开发由志愿者完成，这些持续投入仍然需要有人承担。

## 2. 项目背景与需要解决的问题

### 2.1 已知背景

- 服务对象是家长自发组织的外教一对一英语课 QQ 群，架构文档描述的整体规模约为 1000 名学生、100 名外教老师。
- 第一阶段计划小范围真实试运行，规模为 50 名用户、5～8 个班级，预计同时在线约 10 人。这里的“用户数”与整体“学生数”口径不同，不能直接等同，也不能据此推算实际并发。
- 班长担任班级管理员，负责老师资料、课表、审核和课时维护；老师暂不独立登录。
- 平台定位是资料查询、预约排课和课时记录工具。不包含在线支付，实际授课也需要通过现有方式完成。

### 2.2 现存问题与预期收益

以下问题是根据目标流程提出的业务假设，需要向家长和班长核实发生频率与影响。

| 可能存在的问题                   | 平台预期改善                                                 |
| -------------------------------- | ------------------------------------------------------------ |
| 老师介绍和音频散落在群消息中     | 登录后集中搜索、查看资料与可约时间                           |
| 预约依靠私聊，空档信息更新不及时 | 统一时间段、申请和审核状态                                   |
| 手动修改共享表格完成取消和请假   | 明确截止时间、审核结果和课时影响，支持凭证上传并保留操作日志 |
| 余额和扣课依赖人工记录           | 余额、流水与自动扣课可追溯                                   |
| 班长交接依赖个人聊天记录         | 通过账号、记录和操作说明交接                                 |

## 3. 平台功能范围与阶段边界

### 3.1 阶段 0：规则确认与数据准备（1个月）

产出应包括：老师和学生资料模板、班级归属、初始课时余额确认表、预约与请假规则、负责人名单，以及现状工作量基线。

选择 5～8 个有稳定班长的班级参与准备和试运行，总用户数控制在 50 人以内。

### 3.2 阶段 1：完成试运行核心流程（3个月）

试运行采用 Next.js、Prisma 和 MySQL 8.0 社区版，网站与 MySQL 部署在同一台借用服务器上，由技术志愿者负责数据库维护与备份。时间安排为3个月。保持原有云文档与该系统双线运行至少1个月。

| 能力       | 纳入第一阶段的范围                                                                     | 业务价值或验收重点                                                                                 |
| ---------- | -------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| 账号与权限 | 账号密码登录、家长注册审批、账号启停；总管理员、班长、家长三类权限                     | 未登录不可看老师；班长只管本班；家长只操作本人名下学生                                             |
| 班级与学生 | 建立班级、绑定班长和老师、维护家长与学生关系                                           | 学生归属和初始余额可核对；遵守一班一主要班长、一班长一班、一老师一班的约束                         |
| 老师目录   | 列表筛选、详情、外部音频链接                                                           | 家长能找到合适老师及其可约时间；音频通过外链跳转                                                   |
| 课表与预约 | 按老师维护时间段、提交申请、班长审核、预约记录                                         | 同一时间段不重复占用；主老师限制与重选规则符合约定                                                 |
| 取消与请假 | 待审预约直接取消；已确认预约课前申请取消或请假，支持上传凭证，由班长审核并保留操作日志 | 取消批准后释放时间段；请假批准后不释放时间段；两者均免扣课时；凭证仅供相关家长和有权限的管理员查看 |
| 课时账本   | 人工登记充值、余额和流水查询、课后自动扣课、异常调整留痕                               | 不重复扣课、不扣成负数；待审请假暂缓扣课；异常可追溯                                               |
| 运行保障   | HTTPS、备份、恢复验证、任务异常记录、操作交接说明                                      | 这是使用真实预约和课时数据的前提，需计入交付成本                                                   |

### 3.3 阶段 2：全量上线

试运行核心流程稳定、预约与课时记录核对无误后，面向现有 QQ 群的完整用户群开放，覆盖约 1000 名学生、100 名外教老师对应的班级和家长。功能沿用阶段 1，重点完成正式部署、数据迁移和各班级接入。

| 工作项         | 上线要求                                                                                               |
| -------------- | ------------------------------------------------------------------------------------------------------ |
| 正式环境       | 落实应用服务器、域名和 HTTPS，完成适用的备案要求；将同机自建 MySQL 迁移到阿里云 RDS MySQL              |
| 数据与班级接入 | 保留试运行记录，补齐其余班级、老师、学生和家长资料，由各班长核对课表、有效预约及初始课时余额           |
| 上线验证       | 按预计全量数据和预约高峰验证性能，确认权限隔离、预约冲突控制和自动扣课正常，完成备份恢复与切换回退演练 |
| 运营交接       | 各班长完成操作培训，明确技术维护、异常处理、费用承担及续费负责人，按第 4 节预算落实正式运行资源        |

接入可按班级分批完成，直至覆盖完整用户群。上线后持续检查预约、扣课异常和资源使用情况；如需升级配置，重新核算费用。

## 4. 成本：现金支出与人员时间分别计算

### 4.1 估算口径

以下金额均为人民币。开发和日常维护由志愿者承担，试运行借用现有服务器与域名，正式运营购买应用服务器、RDS MySQL 和域名。平台使用现有渠道授课、音频外链，不集成支付与自动通知。云资源实际费用需按地域、配置、续费价格、流量额度、备份和税费核算；峰值带宽不等于持续可用带宽或无限流量。

### 4.2 一次性建设投入

| 工作项                                 | 承担方式 | 范围说明                                                      |
| -------------------------------------- | -------- | ------------------------------------------------------------- |
| 规则梳理、页面原型、初始数据模板       | 志愿者   | 明确预约、取消、请假、课时规则和验收口径                      |
| 账号权限、老师资料、班级学生、课表预约 | 志愿者   | 包含家长与管理员页面及关键冲突控制                            |
| 取消、请假、课时账本和自动扣课         | 志愿者   | 包含幂等、异常处理、权限与流水核对                            |
| 验证、部署、备份恢复、试点导入和培训   | 志愿者   | 包含真实试点反馈修正                                          |
| 正式开放准备                           | 志愿者   | 自建 MySQL 迁移至 RDS、数据核对、性能验证、切换演练与回退准备 |

暂不计开发人工现金支出，实际排期根据志愿者可投入时间确定。

### 4.3 持续现金支出

| 项目                       | 试运行安排与新增现金支出                       | 正式运营按年估算                         |
| -------------------------- | ---------------------------------------------- | ---------------------------------------- |
| 应用服务器                 | 暂借，暂不新增费用                             | 500～1000 元                             |
| 数据库                     | MySQL 社区版与网站同机部署，无独立数据库服务费 | RDS MySQL 基础版，预留 100～250 元       |
| 域名                       | 暂借，暂不新增费用                             | 50～150 元                               |
| 异机备份、日志和基础监测   | 使用现有资源与闲置本地电脑，暂不另购设备       | 使用现有资源与闲置本地电脑，暂不另购设备 |
| **新增资源费用合计** | **暂按 0 元规划**                        | **约 650～1400 元/年**             |

数据库预算参考 2026-09-05 查询的[阿里云官方活动](https://www.aliyun.com/activity/database/bestoffers)：MySQL 8.0 基础版 2 核 2 GB、50 GB 高性能云盘为 99 元/年；2 核 4 GB、100 GB 高性能云盘为 227.99 元/年。两款均为单节点基础版，同一用户限选一款。活动截至 2027-03-31，活动期内每年最多按优惠价续费一次、每次一年；活动结束或变配后需重新核算预算，超额备份等收费项目另计。

试运行暂不新增资源支出，以资源可借用为前提；闲置电脑仍需在备份时开机联网、检查备份结果并验证恢复，不能将“无新增设备费”理解为“不需要备份”。上述合计未计电费、已有网络费用及志愿者时间。HTTPS 证书可采用免费自动续期方案，但仍有配置和维护工时。音频平台若产生付费或迁移需求，应另计成本。

中国大陆部署时，还应确认域名与备案主体、办理要求和时间；这属于上线准备，不能仅凭服务器购买完成判断可上线。

### 4.4 持续人员投入

| 职责     | 承担人员         | 初始时间估算    | 需要承担的工作                                       |
| -------- | ---------------- | --------------- | ---------------------------------------------------- |
| 技术维护 | 招募技术志愿者   | 每月 4～10 小时 | 更新依赖、查看异常、备份恢复、处理扣课任务和运行故障 |
| 总管理员 | 群主或招募志愿者 | 每月 2～6 小时  | 账号审批、班级调整、全局异常、费用与资料管理         |
| 每班班长 | 班长志愿者       | 每周 1～3 小时  | 更新课表、预约与请假审核、登记充值、对账、人工提醒   |

以上时间需在试点中实测；初期培训、集中排课和故障期间可能显著增加。设实际启用班级数为 N，按每月 4 周简化估算，班长总投入为每月 4N～12N 小时，不能直接用 100 名老师推定有 100 个班级。

例如启用 10 个班级，总人员投入约为每月 46～136 小时，其中大部分是班长运营。应与现有人工流程对比净增减，不能把全部时间都视为平台新增成本，也不能假设上线后人工审核会消失。

### 4.5 总成本与预算判断

按志愿开发和维护、借用试运行资源的方案，试运行暂按无新增资源费用规划；正式运营全年资源预算约为 **650～1400 元**，以第 4.3 节的配置、活动资格和费用边界为前提。正式开放前需明确费用承担方与续费负责人。

志愿者工时单独记录，不折算为实际付款。若以后改为付费开发或维护、增购设备或升级数据库，应重新核算预算；长期预算不能直接用当前活动价乘以年数。

## 5. 可持续性：谁维护、谁出钱、出问题怎么办

### 5.1 人员与交接

- 指定一名业务负责人，负责规则确认、争议升级和范围取舍；指定技术维护人及可接替的备份人员。
- 每班保留一名主要班长，沿用现有权限模型。班长退出时由总管理员执行交接与绑定变更，不能依赖共享密码，也不默认系统已支持多班长共同管理。
- 建立简短操作说明，覆盖建课表、审核、登记充值、课时纠错和故障期间的人工记录方式。
- 代码统一由 github 管理，保证开发与维护人员变更不影响系统更新与迭代。
- 代码、域名、云账号、备份和续费信息必须能由指定接替者接手，避免关键资产仅由离任志愿者掌握。

### 5.2 技术与数据维护

- 试运行时网站与 MySQL 同机部署，共享计算和存储资源，服务器故障会同时影响两者；MySQL 仅供本机应用连接，不开放公网数据库端口。正式面向完整用户群开放前迁移到阿里云 RDS MySQL。当前预算对应单节点基础版，是否满足正式运营的停机容忍度需在开放前确认。
- 关注集中预约、批量审核和自动扣课时的内存占用、磁盘空间、写入延迟、锁等待与错误率；正式开放前验证自建 MySQL 与 RDS 的版本和配置兼容性，并完成数据核对、性能验证、迁移与回退演练。
- MySQL 应采用一致性备份方式，不能仅复制运行中的数据库数据目录并假定备份完整；备份保留在服务器之外，并实际验证恢复。
- 建议试点恢复目标为最多丢失 24 小时数据、一个工作日内恢复。涉及课时账本时，这一数据丢失窗口是否可接受需业务负责人确认；正式运营应重新确定备份频率和恢复目标，并计入成本。
- 明确学生信息的用途、最少必要字段、访问权限与保存期限，向家长说明数据处理方式。退出时的删除、必要记录留存及音频发布授权，应有可执行的处理规则。
- 外部音频可能出现链接失效、登录限制或移动端跳转问题；班长需要定期检查，故障时仍可查看文字资料。

### 5.3 故障与退出安排

服务故障时，由业务负责人决定暂停在线申请，班长通过现有渠道记录新增预约和调整。恢复后先核对时间段、预约和课时流水，再补录并重启自动扣课，避免重复登记。

若项目停运，应提前通知家长，安排最终余额核对，并由授权人员导出必要的老师、课表、预约和课时记录。导出与停运流程属于建议增加的运营要求，需要在正式开放前落实；不能假定架构已经提供相关页面。完成交接和约定的留存处理后，再关闭账号与停止云资源续费。
